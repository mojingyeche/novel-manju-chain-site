能力、适用对象与产物

适合已有小说、故事方案或剧本的创作者。默认按约定范围交付完整 Markdown 剧本，不以片段代替全部集数；如果只需要试写或局部修订，应主动声明范围。

  • 输入：故事材料或既有剧本、目标集数/时长、风格、必须保留内容。
  • 输出：完整剧本、按任务要求提供的修订或检查说明。
  • 形式：集、场次、场景信息、动作与人物对白清晰分层；具体格式以安装版 Skill 为准。
  • 与 Agent 的区别：这是文本业务入口；链式 Agent 额外管理更新、用户确认、冻结和跨阶段交接。

安装与首次使用

旧包内更新工具尚可能引用私有仓库；如自动更新提示权限错误，请从本官网下载完整新版，备份本地修改后按宿主方式安装。公开下载不代表旧更新器已经改造。

0.3.4 正式安装包无需登录即可公开下载；旧版本若标注私有存档，仍需要仓库权限。下载后核对本页对应版本的 SHA256，不要把网页、源码目录或 ZIP 文件本身当作已安装 Skill。

  1. 下载下面一个明确版本的完整套件，在临时目录解压，保留原 ZIP 和校验值。
  2. 本组件位于解压后的 novel-manju-chain-suite/plugin/skills/short-drama-write/。需要单独使用时提取整个目录，保留 SKILL.md、references、scripts 等原有相对结构；不要只复制 SKILL.md。
  3. 备份宿主中同名目录和本机未发布改动，再按宿主支持的 Skill 安装方式安装；最终 Skill 目录根部应直接有 SKILL.md，避免多套一层文件夹。
  4. 重新加载宿主或开启新任务，让它列出实际解析到的 Skill 名称、位置和套件版本。复制文件不等于当前上下文已经重载。
  5. 先做能力说明和依赖检查，再提交真实项目。其他智能体若不支持 Codex 的 Agent TOML，可按其技能加载机制接入；本项目不保证所有平台直接兼容。

推荐下载下方的本 Skill 独立包（0.2.0 起）：核对独立包 SHA256 后解压，将 skills/ 下的完整技能目录分别安装到宿主技能目录。上方完整套件提取方式仍可用；0.1.0 没有独立包。模型账号、生成工具及个人资料库不会随包迁移。

工作机制与确认节点

  1. 判断是创作、改编、修订，还是只做格式整理。
  2. 核对原文是否完整、任务范围及不可改内容；长篇缺失部分不得虚构为已读。
  3. 创作/改编按约定完成整部剧本；修订按具体问题保留未授权改动的语言和情节。
  4. 需要强化开篇时明确要求在整体故事中处理冲突和人物动机，不机械地把每集都写成同一钩子模板。
  5. 按当前任务检查结构、格式与范围，交付可阅读的完整文件；时长估算需承认对白速度及表演差异。

“只审查/比较”不授权修改，“只规范格式”不授权润色对白。是否启用额外开篇检查，取决于明确需求和安装版本规则。

各功能如何调用

以下是可修改的调用示例，不是已经执行过的任务。把附件、编号与目标替换为你的实际项目。

小说转完整剧本

使用 short-drama-write，将附件小说改编为 12 集中文漫剧剧本，每集目标 90 秒。保留人物关系和结局，强化开篇冲突与后续因果。先确认素材是否完整，最终交付全部 12 集的一份剧本.md。

这是直接使用文本 Skill，不自动启动资产或导演流程。

保留原文，只整理格式

使用 short-drama-write，只规范附件剧本的集、场次、动作和对白格式。保留所有原对白和剧情，不润色、不补情节；无法判断的地方列疑问。

适合剧本已经确认，只需要结构整理的情况。

定向修订而非重写全文

使用 short-drama-write，修订附件第 3 集中主角突然获知秘密的因果缺口，保留结尾反转和其余已确认对白。先说明所需调整范围，再完成获准的修改并检查前后影响。

指出具体缺口和保留项，可避免不必要的全篇风格重写。

能力边界与常见问题

  • 不生成角色资产、场景图、视频或正式导演分镜；这些分别由其他入口负责。
  • 不把“节奏更快”理解成删除必要因果，不承诺商业成绩或精确成片时长。
  • 直接调用本 Skill 不等于调用链式 Agent 的全部状态机；需要全流程时使用 Agent 指南。
  • 不自动改用 drama-creator 或其他写作模型。
