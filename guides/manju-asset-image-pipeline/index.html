能力、适用对象与产物

适合需要长期维持角色、服装、场景和重要道具一致性的漫剧项目。它不只是“提几个角色名字然后生图”。

  • 输入：完整剧本、确认版本、视觉风格、资产范围及可用生成工具。
  • 中间产物：剧情实体与状态清单、证据、差异矩阵、资产说明和生成计划。
  • 最终产物：实际生成且验收的图片、资产索引和问题记录；没有调用成功的图片不得写成已生成。
  • 人物与场景辅助能力分别依赖 manju-character-card、manju-scene-grid；单独提取总控目录不包含这些依赖。

安装与首次使用

旧包内更新工具尚可能引用私有仓库；如自动更新提示权限错误，请从本官网下载完整新版，备份本地修改后按宿主方式安装。公开下载不代表旧更新器已经改造。

0.3.4 正式安装包无需登录即可公开下载；旧版本若标注私有存档，仍需要仓库权限。下载后核对本页对应版本的 SHA256，不要把网页、源码目录或 ZIP 文件本身当作已安装 Skill。

  1. 下载下面一个明确版本的完整套件，在临时目录解压，保留原 ZIP 和校验值。
  2. 本组件位于解压后的 novel-manju-chain-suite/plugin/skills/manju-asset-image-pipeline/。需要单独使用时提取整个目录，保留 SKILL.md、references、scripts 等原有相对结构；不要只复制 SKILL.md。
  3. 备份宿主中同名目录和本机未发布改动，再按宿主支持的 Skill 安装方式安装；最终 Skill 目录根部应直接有 SKILL.md，避免多套一层文件夹。
  4. 重新加载宿主或开启新任务，让它列出实际解析到的 Skill 名称、位置和套件版本。复制文件不等于当前上下文已经重载。
  5. 先做能力说明和依赖检查，再提交真实项目。其他智能体若不支持 Codex 的 Agent TOML，可按其技能加载机制接入；本项目不保证所有平台直接兼容。

推荐下载下方的本 Skill 独立包（0.2.0 起）：核对独立包 SHA256 后解压，将 skills/ 下的完整技能目录分别安装到宿主技能目录。本包包含总控、manju-character-card、manju-scene-grid 三个独立目录，必须一起安装。上方完整套件提取方式仍可用；0.1.0 没有独立包。模型账号、生成工具及个人资料库不会随包迁移。

工作机制与确认节点

  1. 从完整剧本提取上下文、年代与世界规则；区分原文事实、推断与新增提案。
  2. 确认视觉方向和资产范围，建立人物/场景/道具及造型、视图、状态链。
  3. 制定资产契约与差异矩阵，避免角色撞脸、服装不分层和状态混用。
  4. 形成描述与生图简报，核对已授权的辅助 Skill、模型及生成范围。
  5. 先试生和验收，再在授权范围内批量生成；超出已授权范围的新增数量或换工具需要确认。
  6. 检查真实图片与剧情一致性，交付编号文件、清单、路径和验收结果，供导演引用。

0.2.0 起输出到已确认的可写项目根目录下，不再要求发布者盘符。回退到 0.1.0 时仍须注意旧版固定输出目录假设，不应盲目创建同名盘符目录。

各功能如何调用

以下是可修改的调用示例，不是已经执行过的任务。把附件、编号与目标替换为你的实际项目。

先拆资产，不生图

使用 manju-asset-image-pipeline。附件是已确认的完整剧本。本次只做资产拆解、剧情证据、角色造型与场景道具状态链，提出视觉方向与生成计划；不调用生图工具，不把推断写成原文事实。

适合先确认需要做哪些素材以及预算范围。

确认范围后试生

继续当前资产项目。我确认已列出的视觉方案和资产范围。本次只授权清单中明确选定资产的试生，请先核对实际资产编号、可用工具与输出目录；不自动扩展批次、追加重试或换模型。

使用真实清单中的编号和数量，不要直接把示例当作完整生成授权。

已有图片验收与交接

使用 manju-asset-image-pipeline，根据附件冻结剧本、资产清单和实际图片进行验收，检查身份、服装状态、场景与重要道具一致性。列出问题及对应文件；未获同意不重生成。通过项整理为可供导演引用的索引。

验收需要图片本身可读取，只看到文件名不能证明画面合格。

能力边界与常见问题

  • 生图依赖目标电脑的工具和账号，安装包不会携带凭据，也不保证模型一定可用。
  • 它不是剧本改写或最终视频制作入口；发现剧本变动要回到确认版本处理。
  • 资产助手依赖须在授权范围内使用；套件包含依赖不等于用户授权了全部付费操作。
  • 路径、哈希和文件存在性检查不等于视觉质量验收；必须区分机械验证和实际看图。
