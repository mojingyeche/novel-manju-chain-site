能力、适用对象与产物

适合希望把改编、审稿和制作串在一起的创作者。小说入口只比剧本入口多一步“转完整剧本”，不先生成另一部长篇小说。已有剧本直接进入审查。

入口你提供本阶段产物
小说改编完整小说、目标时长/集数、风格、不可改内容完整剧本，随后审查
已有剧本剧本文件、风格、审查范围带位置证据的问题清单与优化方案
确认修订获准问题编号、保留项修订剧本、变更说明、复核结果
冻结后制作明确冻结版本、资产与工具授权资产文件及清单、导演规划、最终分镜提示词

三个核心 Skill 各司其职：剧本创作负责文本，资产总控负责资产，导演负责分镜。它们不是三个自动替你开新任务的聊天窗口。

安装与首次使用

旧包内更新工具尚可能引用私有仓库；如自动更新提示权限错误，请从本官网下载完整新版，备份本地修改后按宿主方式安装。公开下载不代表旧更新器已经改造。

0.3.4 正式安装包无需登录即可公开下载；旧版本若标注私有存档，仍需要仓库权限。下载后核对本页对应版本的 SHA256，不要把网页、源码目录或 ZIP 文件本身当作已安装 Skill。

  1. 下载下面一个明确版本的完整套件，在临时目录解压，保留原 ZIP 和校验值。
  2. 使用包内 README 和安装脚本安装套件；它包含编排 Skill、三个核心 Skill、两个资产辅助 Skill 和 Agent 配置。
  3. 备份宿主中同名目录和本机未发布改动，再按宿主支持的 Skill 安装方式安装；最终 Skill 目录根部应直接有 SKILL.md，避免多套一层文件夹。
  4. 重新加载宿主或开启新任务，让它列出实际解析到的 Skill 名称、位置和套件版本。复制文件不等于当前上下文已经重载。
  5. 先做能力说明和依赖检查，再提交真实项目。其他智能体若不支持 Codex 的 Agent TOML，可按其技能加载机制接入；本项目不保证所有平台直接兼容。

完整套件是 Agent 推荐安装方式。解压后在 novel-manju-chain-suite 中运行 python install.py --codex-home <宿主配置目录>。模型账号、生成工具及个人资料库不会随包迁移。安装到其他智能体时应按其技能加载方式接入，不保证 Codex Agent 配置直接被识别。

工作机制与确认节点

  1. 启动检查：正式调用先检查更新；有新版展示时间、组件和变化，用户决定是否安装。检查失败应说明并询问是否离线继续。
  2. 收集需求：识别小说/剧本，询问尚未明确的目标时长、风格、平台及改编边界；已提供的内容不必重复填写。
  3. 小说转剧本：仅小说入口执行。把开篇冲突、核心人物动机、情节承接与漫剧节奏落实到完整剧本，不用前三章样稿冒充全文。
  4. 只审查：检查对白 AI 化、前后因果与信息来源、人设、重复、格式、开篇和整体节奏；输出问题位置、严重程度、影响与方案，此时不暗改原文。
  5. 用户选范围：确认问题编号、允许改动的部分和必须保留的部分；没有确认不能将建议直接变成正式改稿。
  6. 修订与复核：按确认范围修改，检查改动对全文的影响；结果交用户确认冻结，记录版本与哈希。
  7. 制作：基于同一冻结剧本进行资产统筹与导演前期规划。需要新增依赖、额外生成或改变范围时单独确认。
  8. 最终交付：真实资产可追溯后完成绑定分镜，复核动作、空间、对白对象和上下组承接，报告实际文件与未完成项。

确认使用工具、确认修改哪些剧情、确认冻结是不同决定，不能互相替代。只要审稿时可以停在问题清单，不必走完整制作链。

各功能如何调用

以下是可修改的调用示例，不是已经执行过的任务。把附件、编号与目标替换为你的实际项目。

1. 小说改编，先确定需求

调用小说/漫剧链式 Agent。附件是完整小说。目标总时长 30 分钟，计划 20 集，二维国风风格。保留主角动机、人物关系和结局，可调整事件顺序。先检查更新和输入完整性，补问必要信息，再把小说改成完整剧本；审查后等我确认优化范围。

集数与时长是你的目标，不是质量保证；冲突或信息不足时先对齐。不能仅说“改成爆款”就默认补齐所有偏好。

2. 已有剧本，只审不改

调用小说/漫剧链式 Agent。附件为已有剧本，目标是都市写实漫剧。本次只审查全文：对白 AI 化、因果、人设、重复、格式、开篇与节奏。列问题编号、原文位置、影响和建议，不改正文，不生成资产。

明确只读边界，避免“优化一下”被理解为立即全篇改写。

3. 按编号修订

继续当前项目。我同意修复上一份清单中的 P01、P03、P07；其余暂不改。保留结局和主角底线。完成后交付完整修订剧本、变更说明与复核结果，再等我确认冻结。

请使用实际问题编号；不要把这里的示例编号当作已有问题。

4. 冻结并进入资产阶段

我确认冻结刚刚复核的剧本版本。请记录其真实路径和哈希。本阶段授权资产总控进行拆解、状态链与视觉方案；先列所需资产和依赖，未确认生成范围前不生图。

若你已明确给出生成数量与工具授权，无需重复同范围确认；新增角色、模型或批次不能自动扩展。

5. 交付绑定素材的分镜

继续当前冻结项目。使用已确认的导演 Skill，根据冻结剧本与已验收资产生成最终分镜提示词。先核对资产实际路径与版本，不改剧情；缺素材时列清单，不把占位符作为已绑定成品。

这一步产出的是制作提示词，不是自动生成完成的视频。

6. 中断后续作或改变剧情

继续这个项目。请读取项目当前状态、最近确认记录、冻结剧本及交付索引，说明停在哪个阶段、还缺什么，再继续已授权部分。如果本次剧情改动影响冻结版本，请列受影响资产和分镜，等我确认新的冻结版本。

新任务需要可访问的项目文件；不要只靠旧聊天印象续作，也不要把旧素材直接认定为适配新剧情。

能力边界与常见问题

更新后能否立即在同一上下文使用新版？

不能保证。安装与重新加载是两件事；安装成功后应停止旧版本流程，按宿主要求重载或新开任务，再核对版本。维护与能力解释不触发创作链，也不为了说明用法安装新版。

如何回退和固定版本？

先备份本地改动，选下方明确旧版本并核对它自己的 SHA256。0.2.0 更新器可在编排 Skill 目录运行 python scripts/update_from_github.py --version <版本> --confirmed，安装后重载；它记录版本固定，后续支持此能力的检查器不自动建议升级。取消固定：python scripts/check_for_updates.py --unpin --confirmed。回退到 0.1.0 后，旧检查器不识别此设置，仍需拒绝升级提示。恢复安装器备份使用包内 python install.py --codex-home <同一配置目录> --restore <备份目录> --confirmed。这些命令只能在用户确认后执行。旧版本不足时不补假链接。

本机优化后会自动发布吗？

不每小时检查，也不未经同意推送。优化完成、验证后整理统一更新说明，询问是否同步；同意后才执行发布与网站同步。跨仓库步骤失败要报告未完成位置，不能宣称已同时上线。其他工具在后台修改文件不会自动被本 Agent 感知。

能否跨电脑开箱即用？

还需要兼容的宿主、模型工具和可写输出目录；公开下载安装包不需要 GitHub 权限。0.2.0 资产输出改为已确认的项目目录；0.1.0 的旧目录假设仍需注意。独立 Skill 包不含链式更新器，独立安装后应主动查看本页更新并确认安装。私人模型账号、权限及资料库不会随包迁移。

安全校验能保证什么？

校验值用于检查下载内容与官方记录一致，不等于数字签名或账号不会被盗。安装器对可捕获的失败进行恢复；断电或强杀留下锁和备份时需人工核验，不能保证自动灾难恢复。

会自动替我生成视频或无限重试吗？

不会。生成工具、成本和范围受当前授权限制；指定模型不可用时报告阻塞，不自动换模、扩量或无限重试。真实出图及视频制作仍受工具能力影响。
