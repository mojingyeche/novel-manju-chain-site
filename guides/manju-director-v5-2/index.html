能力、适用对象与产物

适合已有确定剧本、希望把剧情落实为可制作镜头的创作者。输入应包含实际剧本、风格、资产情况及需要延续的上一组状态；输出是导演规划和提示词，不是已生成的视频。

  • 关注人物位置、朝向、动作接续、对白对象、镜头动机与跨组承接。
  • 正式输出遵循 Skill 自带结构；本网页只介绍用法，不替代或公开完整私有模板。
  • 已有素材时绑定真实资产；独立调用允许按其规则制作未绑定素材的完整文本版，但必须明确标注待绑定。

安装与首次使用

下载入口指向私有 GitHub 仓库。先取得仓库访问权限并登录；公开指南不代表安装包已公开。下载后核对本页对应版本的 SHA256，不要把网页、源码目录或 ZIP 文件本身当作已安装 Skill。

  1. 下载下面一个明确版本的完整套件，在临时目录解压，保留原 ZIP 和校验值。
  2. 本组件位于解压后的 novel-manju-chain-suite/plugin/skills/manju-director-v5-2/。需要单独使用时提取整个目录，保留 SKILL.md、references、scripts 等原有相对结构；不要只复制 SKILL.md。
  3. 备份宿主中同名目录和本机未发布改动，再按宿主支持的 Skill 安装方式安装；最终 Skill 目录根部应直接有 SKILL.md，避免多套一层文件夹。
  4. 重新加载宿主或开启新任务，让它列出实际解析到的 Skill 名称、位置和套件版本。复制文件不等于当前上下文已经重载。
  5. 先做能力说明和依赖检查，再提交真实项目。其他智能体若不支持 Codex 的 Agent TOML，可按其技能加载机制接入；本项目不保证所有平台直接兼容。

推荐下载下方的本 Skill 独立包（0.2.0 起）：核对独立包 SHA256 后解压，将 skills/ 下的完整技能目录分别安装到宿主技能目录。上方完整套件提取方式仍可用；0.1.0 没有独立包。模型账号、生成工具、私有仓库权限及个人资料库不会随包迁移。

工作机制与确认节点

  1. 核对剧本、覆盖范围、风格与素材是否可访问；链式 Agent 中先确认冻结。
  2. 理解场景动作、人物关系及空间，形成导演规划；不能为镜头好看擅自改写剧情。
  3. 按原生格式落实分镜与提示词，非开场组承接前组状态。
  4. 逐组检查动作因果、人物位置、对白指向与结尾状态，避免每组像重新开场。
  5. 交付完整提示词文件并标明素材绑定状态；链式最终交付必须具有真实资产路径和版本。

“独立导演未绑定文本版”和“链式 Agent 已绑定最终版”是两种不同交付状态；前者不能冒充后者。

各功能如何调用

以下是可修改的调用示例，不是已经执行过的任务。把附件、编号与目标替换为你的实际项目。

冻结剧本与素材转分镜

使用 manju-director-v5-2。附件是已确认剧本与验收资产清单。按原生流程生成完整导演分镜及 Seedance 2.0 提示词；不改剧本，重点检查空间、动作和对白对象的连续性，标出真实引用素材。

在链式 Agent 内还需核对正式冻结记录。

暂时没有素材，只做文本版

独立使用 manju-director-v5-2。根据附件剧本生成未绑定素材的完整文本版，按 Skill 规则保留待绑定标记，并另列缺失素材。不得声称已经绑定或可以直接作为链式最终交付。

允许先看导演方案，但不伪造参考图或可追溯路径。

续做与连续性修订

使用 manju-director-v5-2，继续附件已有分镜。先读取上一组结尾状态，再处理后续已指定范围。保留原生字段及命名，不改对白；发现前组空间状态冲突时列出影响并提出修复方案。

同时提供上一组和对应剧本，不能仅说“接着写”而省略必要状态。

能力边界与常见问题

  • 导演提示词不等于视频成片，视频模型和生成授权需要单独具备。
  • 不能保证任何平台直接接受所有提示词长度或字段，实际提交需遵守目标工具限制。
  • 缺素材可以如实交付未绑定文本版，但链式最终交付的真实资产门槛不变。
  • 正式模板、阶段和命名以所安装的 Skill 为准，不用网站示例替代检查器。
